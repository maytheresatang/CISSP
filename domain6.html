🚨 Nessus vs Nikto — Most Tested Tool Confusion Nessus = general network/host vulnerability scanner. Nikto = specifically web server testing (HTTP/HTTPS). If the scenario involves a web server on port 80 or 443 → Nikto. If it's a general network vulnerability scan → Nessus.
Nmap Port States
StateMeaning
OpenAn application is actively accepting connections on the port
ClosedPort is reachable and responds, but nothing is listening
FilteredA firewall/filter stops probes reaching the port — nmap can't tell if it's open
UnfilteredPort is reachable but nmap can't tell open from closed (ACK scan result)
Open|FilteredCan't tell open from filtered — open ports that give no response (UDP, FIN, NULL, Xmas scans)
Closed|FilteredCan't tell closed from filtered (IP ID idle scan only)

The Sybex study guide teaches three states (open, closed, filtered); nmap itself reports six.

🎯 Practice Q Review · Missed / Unsure
You are scanning with nmap. It detects that a port is open on a remote system but receives no responses to its probes to that port. What status will nmap report?
✅ Open|Filtered
Nmap uses Open|Filtered when it can't distinguish an open port from a filtered one — which happens exactly when an open port stays silent. Unfiltered means reachable but undetermined; Open requires a positive response; "Unfiltered Open" isn't an nmap state.
TCP Scan Types
ScanHow it worksNotes
TCP connectCompletes the full three-way handshake (SYN → SYN/ACK → ACK)Noisy, logged by the target; no special privileges needed
TCP SYN ("half-open")Sends SYN, receives SYN/ACK, replies RST — never completes the handshakeStealthier; nmap's default with root
TCP ACKSends ACK packets to map firewall rulesShows filtered vs unfiltered — not open vs closed
Xmas / FIN / NULLUnusual flag combinations (FIN+PSH+URG / FIN only / no flags)Evade simple filters; open ports often don't respond
🎯 Practice Q Review · Missed / Unsure
Which scan type completes the TCP three-way handshake as an attack?
✅ TCP connect scanning
A connect scan makes a full connection. A SYN scan deliberately stops halfway (half-open). An ACK scan maps firewall rules. "TCP remote scanning" is not a real scan type.

Penetration Test Phases
  1. Planning / Scoping — Define scope, get written authorisation (rules of engagement). Critical: no test without written permission.
  2. Reconnaissance (Recon) — Passive: OSINT, WHOIS, LinkedIn. Active: port scanning, banner grabbing.
  3. Scanning / Enumeration — Identify live hosts, open ports, services, OS. Tools: Nmap, Nessus.
  4. Exploitation — Attempt to exploit discovered vulnerabilities. Tools: Metasploit, custom exploits.
  5. Post-Exploitation / Lateral Movement — Escalate privileges, pivot to other systems, establish persistence.
  6. Reporting — Document findings, evidence, impact, and remediation recommendations.
  7. Cleanup / Remediation Verification — Remove artefacts. Re-test after fixes.
⚠️ Rules of Engagement (RoE) Written authorisation is NON-NEGOTIABLE before testing. Without it, penetration testing is criminal. RoE defines: scope (IP ranges, systems), timing (business hours vs off-hours), escalation contacts, off-limits systems.

⚠️ "Lessons learned" is NOT a pen test phase Lessons learned is the final phase of incident response. Pen tests end with reporting.
🎯 Practice Q Review · Missed / Unsure
Which of the following is NOT a valid phase of a penetration test? (Reporting · Exploitation · Information gathering and discovery · Lessons learned)
✅ Lessons learned
It belongs to the incident response lifecycle. The other three are core pen test phases.
🎯 Practice Q Review · Missed / Unsure
Of the various ways to gather information about a target, which would a penetration tester be LEAST LIKELY to use in the scanning and probing phase? (Port scanning · Vulnerability scanning · Searching DNS records · Using Nmap)
✅ Searching Domain Name System (DNS) records
Searching DNS records (along with WHOIS and OSINT) is passive reconnaissance done earlier, in information gathering. Port scanning, vulnerability scanning and Nmap actively probe the target — the definition of scanning and probing.
Audit Types
TypeDescription
Internal AuditConducted by internal audit function. Less independent but more frequent and contextual.
External AuditConducted by an outside, independent auditing firm hired by the organisation itself. More credible than internal; required for regulatory compliance (SOX, PCI).
Third-Party AuditConducted by, or on behalf of, another organisation (e.g. a regulator or a customer). That other organisation initiates it, chooses the auditors and sets the scope — your organisation is the subject, not the client. SOC reports let a service provider satisfy many third parties with one audit.
Certification AuditLeads to formal certification (ISO 27001, PCI-DSS). Stage 1 = document review. Stage 2 = implementation test.
Compliance AuditAssesses adherence to regulatory requirements (GDPR, HIPAA).
SOC Reports (SSAE 18 / AICPA)
ReportAudienceWhat it coversType 1 vs Type 2
SOC 1Financial auditors of user organisationsControls over financial reporting (ICFR)Type 1 = point in time. Type 2 = period (6–12 months).
SOC 2Security-focused: customers, business partnersTrust Service Criteria: Security, Availability, Processing Integrity, Confidentiality, PrivacyType 1 = design. Type 2 = design + operating effectiveness over time.
SOC 3General publicHigh-level summary of SOC 2 controls. No detailed testing results.Published on website.
📌 Practical Usage: SOC 2 Type 2 In your vendor assurance role, you request SOC 2 Type 2 reports — they show controls were operating effectively over a period (not just designed correctly). A Type 1 is weaker evidence for ongoing assurance.
⚠️ Exam Trap: SOC 1 vs SOC 2 SOC 1 = financial reporting controls. SOC 2 = security and operational controls. Never mix these up. A cloud hosting provider showing their security posture → SOC 2. A payroll processor showing financial control reliability → SOC 1.
🎯 Practice Q Review · Missed / Unsure
What distinguishes a third-party audit from an external audit?
✅ A third-party audit is conducted on behalf of another firm
An external audit is performed by an outside auditor that your organisation hires. A third-party audit is initiated by another organisation (a regulator, a customer), which picks the auditor and the scope.
  • "Multiple firms in one audit" and "the public testing controls" don't distinguish the two types.
  • "Conducted by a firm other than the audited organisation" is true of both, so it isn't a distinction either.

🎯 Practice Q Review · Missed / Unsure
Which of the following is LEAST LIKELY to be the audience of a security audit report? (Board of directors · Government regulators · Large enterprise customers of the audited organisation · Functional management)
✅ Functional management
Audit reports provide independent assurance to those who oversee the organisation or rely on it: the board / audit committee and senior management, regulators, and customers (often via SOC 2 reports). Functional (line) managers usually receive the specific findings they must remediate, not the audit report itself.

AcronymFull NamePurpose

CVSSCommon Vulnerability Scoring SystemNumeric severity score 0–10 for vulnerabilities
CCECommon Configuration EnumerationUnique identifiers for system configuration issues (misconfigurations)

📌 CVE vs CVSS distinction CVE = the unique ID (name). CVSS = the score (severity number). CVE-2021-44228 is Log4Shell. Its CVSS score was 10.0 (critical). Know the difference.

Regression Testing

Regression testing = re-running a test suite after changes to verify previously passing tests still pass. Confirms new code changes don't break existing functionality. Essential in CI/CD pipelines.

🎯 Practice Q Review · Missed / Unsure
An organisation wants a formal inspection of all software before any time is spent on dynamic analysis testing. What would be the MOST formal and in-depth approach?
✅ Fagan inspection
Fagan is the most formal code review: defined roles (moderator, author, reader, recorder, inspectors) and six steps — Planning → Overview → Preparation → Inspection → Rework → Follow-up.
  • Peer review is less formal.
  • Static testing is the broad category (often automated tools), not a specific formal process.
  • Fuzz testing is dynamic — the question says before dynamic testing.
KPI vs KRI — Critical Distinction
KPI (Key Performance Indicator)KRI (Key Risk Indicator)
MeasuresHow well controls and processes are performing nowLeading signal of increasing risk — predictive
Time orientationLagging indicator (historical)Leading indicator (forward-looking)
Example% of critical patches applied within 30 days = 94%Increase in failed login attempts = rising brute-force risk
Used byOperations team to show control effectivenessRisk function to identify emerging risk
Action when threshold breachedInvestigate control failureEscalate risk to risk committee, consider control enhancement
✅ Key Distinction In your role, you design KRIs for the risk dashboard and monitor KPIs reported by 1LoD. Map this directly to CISSP questions about security metrics design and reporting to senior management.
Synthetic Transactions

Synthetic transactions = scripted test transactions run against production systems to continuously verify availability and performance without real user traffic. Simulates what a user would do (login → search → checkout) and validates the full path is working.
